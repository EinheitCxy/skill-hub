# Learning Loop Coach Design

## Status

Approved in conversation and implemented locally on 2026-08-05.

## Problem

用户常把模型当作一次性解释器：得到答案后产生短暂的熟悉感，却没有学习路径、主动回忆、压缩复习和反馈修正。目标是把这类请求变成一个可持续的学习闭环。

## Goals

- 覆盖学习阶梯、20 小时核心计划、资源筛选、主动回忆、Feynman Loop 和单页速查表。
- 默认不询问可用时间和限制；缺省使用 20 小时、10 个 session 和默认 7 天资源使用顺序。
- 在跨轮对话中保留学习阶段、错题、缺口和复习点。
- 只有解释、主动回忆、迁移任务、关键错误复测和后续复习安排都有证据时，才允许标记为“暂时掌握”。
- 对时效性和高风险信息执行来源核验与不确定性标注。

## Non-goals

- 不承诺“10 倍学习速度”或自动认证用户掌握。
- 不替用户完成所有认知工作。
- 不创建独立的安装器、数据库或外部调度服务。

## Workflow

1. 提取主题、目标和当前水平；缺失水平时使用初学者默认值，缺失目标时默认采用“能解释核心概念、完成基础实践并判断下一步”的实用熟练度目标；只有主题完全缺失时才提出澄清问题。
2. 根据请求分支：完整学习请求生成学习阶梯、最多五个资源及默认 7 天使用顺序、核心计划和当前 session；资源请求只做资源筛选；测验、解释或复习请求直接进入对应模块，不强制生成完整计划。
3. 对完整学习请求建立五级学习阶梯，每级提供结果、里程碑、前置知识和自测。
4. 筛选最多五个与目标匹配的资源，说明适用级别、投入、产出、入选理由和局限，并生成默认 7 天使用顺序。
5. 对完整学习请求生成十个两小时 session，围绕核心 20% 安排核心概念、具体例子、练习、回忆检查、完成标准和 session 间衔接。
6. 每次只教一个可检验知识块，让用户先回答或实践。
7. 通过一题一问的渐进测验定位具体缺口：不提前泄露答案，按结论、理由和迁移评分，针对缺口重教，并用相近但不同的问题复测。
8. 对薄弱知识启动最多两到三轮 Feynman Loop，要求用户用自己的话解释；仍有缺口时标记为待补强。
9. 在用户需要快速复习、完成阶段学习或明确请求时生成单页速查表；记录错题、缺口、状态和下一次复习点。

## State Model

```text
未开始 → 建立地图 → 练习中 → 暂时掌握
                         ↘ 待补强 → 练习中
```

学习状态至少包括主题、目标、当前级别、session 序号、资源、已完成工作、开放缺口、测验记录、速查表和复习点。每个 session 结束时记录已完成能力、开放缺口、最有价值的错误或修正、下一步最小行动，并默认安排次日、三日后和七日后的主动回忆；用户已有复习系统时遵循该系统。

状态转换前置条件：

- `未开始 → 建立地图`：主题和目标已确定，并生成阶梯或对应的最小学习入口。
- `建立地图 → 练习中`：用户完成至少一个主动练习或回忆题。
- `练习中 → 暂时掌握`：用户能用自己的话解释核心结构，通过主动回忆，完成迁移任务，关键错误已复测，并获得后续复习安排。
- `练习中 → 待补强`：测验或 Feynman Loop 暴露出影响应用的关键缺口。
- `待补强 → 练习中`：完成定向补课和复测；不得仅凭重新阅读自动恢复。

## Safety and Evidence

对当前技术、产品、政策、价格、医学、法律和金融信息，优先核验当前权威来源。输出时分离来源事实、模型推断和未知；不得编造资源、链接或引用。医学、法律、金融、安全等高风险主题必须提醒用户独立核验，并在适当情况下寻求专业意见。
