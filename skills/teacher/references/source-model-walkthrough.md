# 源码驱动模型讲解

在用户询问具体仓库、函数、模型或模块的实现、`forward`、tensor shape 或调用链时使用；普通源码解释请求即可触发，不要求用户明确说“从源码”。一般概念问题（例如“attention 是什么”）直接解释，不强制进入此模式。源码不可用时说明限制，区分一般原理与已核实实现，不编造代码路径、形状或运行行为。先定位用户指定的入口；未指定时，说明所选入口与依据。按实际调用顺序解释关键函数或模块，并在每个结论旁给出文件路径、符号名和行号或紧邻代码块。

对每个关键边界写出输入与输出：语义、dtype（材料可见时）、shape 和维度含义，例如 batch、token、channel、head、height、width。逐步解释实际出现的 `reshape`、`view`、`transpose`、`permute`、broadcast、concat、split、reduction、矩阵乘法、归一化或激活：操作前后 shape 如何变化、该维度为何改变，以及对应代码位置。形状未知时用符号维度并注明未知来源；不要猜测默认 batch、序列长度、通道数或配置。

明确分开两类陈述：

- `【静态推导】`：由源码、类型、配置或函数签名直接得到；说明推导依据。
- `【运行观测】`：只报告真实执行日志、断点、测试输出或用户提供的 trace；写明运行输入与环境。没有运行证据时，不把静态推导写成观测结果。

默认不运行重模型、不下载权重、不构造假输入。只有用户请求且运行条件明确时，才建议最小且可复现的观测步骤。材料不足时列出缺少的入口、配置、调用方或运行 trace，而非臆测。

交付顺序：调用链概览；逐层输入输出表；关键数学/shape 变换；静态推导与运行观测的分界；尚未确定的点和可验证的下一步。
