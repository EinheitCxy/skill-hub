# Subskills and Tools

Use the smallest available set and read each selected skill fully before acting. Select a capability only when the current step lacks it; this table is not a checklist or fixed sequence.

| Need | Preferred capability |
| --- | --- |
| Search design and synthesis | Use this skill’s corpus workflow; do not reload a same-named skill |
| arXiv full-text explanation | `read-arxiv-paper` |
| Scholarly metadata discovery | `arxiv-database`, `openalex-database` |
| Citation and bibliography handling | `citation-management` |
| PDF extraction or inspection | `pdf` |
| Scientific claim audit | `scientific-critical-thinking` |
| Academic prose | `scientific-writing` |
| Diagrams | `markdown-mermaid-writing`, `scientific-schematics` |
| Formula-heavy Markdown or HTML | available LaTeX/document rendering skill |
| Long-running durable research | `planning-with-files` |

## Selection Rules

1. Use project-local sources before repeating live discovery.
2. Use primary scholarly sources for technical claims.
3. Use live search for drift-prone or frontier information.
4. Prefer structured APIs for inventory and metadata; use browser inspection for pages, PDFs, and rendered output.
5. If a named tool is unavailable, state the limitation and use the nearest evidence-preserving alternative.
6. Do not let tool availability change the evidence label.
7. Never install, configure, or mutate an external service unless the user requested it.
