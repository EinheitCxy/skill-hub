# 全流程 Profiling

仅在用户要求耗时、显存、内存峰值或性能瓶颈分析时读取。先检查项目已有测量入口，使用能回答问题的最小工具组合，不默认生成大 trace 或执行完整训练。

## 测量合同

- 选择代表性真实输入并说明选择依据：batch、分辨率、序列/动作长度、采样步数、有效长度与 padding、动态分支。小样本或合成输入只支持对应范围的结论；保留输入标识、配置、模型版本和硬件/软件环境。
- 定义输出何时可用及计时起止位置。分别标明启动/权重加载、数据读取、预处理、主机到设备传输、模型执行、设备到主机传输、后处理与必要落盘；只列实际存在的阶段，标注代码位置。训练请求另列 forward、backward、optimizer。
- 区分完整进程启动到结果、已加载服务的请求到结果、纯模型执行。明确是否含排队、通信和 I/O，不把模型 forward 时间称为全流程。
- 区分新进程冷启动、首次编译/算法选择、预热后的稳定执行；记录预热与测量次数。分别说明文件页缓存、模型/KV 缓存、编译缓存和分配器状态。新进程不代表文件冷缓存；未知就标未知，不默认清空系统缓存或每轮释放缓存。

## 时间

1. 使用单调高精度墙钟测端到端耗时。异步 GPU 工作在计时窗口前排空已有工作，结束读表前等待相关设备的工作完成；启动指标用覆盖启动的外层计时，不能为预先同步而漏掉初始化。多设备说明同步范围。
2. CUDA events 仅用于对应设备/stream 的执行区间，并等待事件完成。它不包含全部 CPU、I/O 或排队时间，不能替代端到端墙钟。
3. 分阶段诊断可用事件或 trace；不要在正式端到端测量的每个阶段强制同步而破坏重叠。重叠阶段、嵌套算子和多 stream 时间不能直接相加为总耗时。
4. 冷启动与稳定执行分别报告样本数、耗时分布和波动。样本足够时才解释尾部分位数；记录统计方式，不用单次快跑代表普遍性能。

## 峰值口径

| 指标 | 必须说明 |
| --- | --- |
| GPU allocated peak | 框架分配器追踪的活跃分配；记录设备、基线、窗口起止及计数器重置位置 |
| GPU reserved peak | 分配器保留内存，独立于 allocated 报告，不相加 |
| 设备/进程显存 | 驱动或外部工具采样口径，可能含上下文、库及非框架分配；区分目标进程和整卡其他负载 |
| 主机内存峰值 | 明确 RSS、PSS 或 USS、目标进程/子进程范围、采样间隔与单位；Python 对象分配量不等于进程 RAM |

- 在请求窗口前记录常驻基线并重置可重置的峰值统计，窗口完成后读数。重置统计不会释放模型或缓存。分别报告绝对峰值及相对基线增加量，后者不等同于所有临时分配之和。
- 启动/加载峰值与预热后请求峰值分开测；请求窗口统计不能证明完整进程峰值。进程生命周期高水位不能当作可重置的阶段峰值，必要时用独立进程或时间序列区分窗口。
- 全流程峰值不能由各阶段峰值相加得到；跨 GPU 或子进程的总峰值需对齐时间，不能相加各自历史最大值。RSS 求和可能重复计入共享页，说明这一限制。
- 外部采样可能漏掉短峰值，称为“采样观测峰值”并记录频率；未测指标写未测，不填零。

## 工具与归因

先用已有日志、墙钟、分配器峰值与进程内存采样。仅在瓶颈无法解释时，对代表输入运行短 profiler：PyTorch 可用 `torch.profiler` 记录 CPU/GPU 活动，按需开启 shape、memory 或 stack；跨线程、传输与 kernel 时间线可选适配设备的系统 profiler。依据实际框架版本核验 API，不把 CUDA 方法套到其他后端。

诊断 trace、hooks、shape/stack 记录会干扰耗时或内存。用独立的低开销运行给最终性能数字，记录诊断开销和执行条件；将瓶颈定位到阶段、操作、输入形状和源码位置，源码推断不能替代运行证据。不保存 tensor 本体来记录 shapes，以免延长其生命周期。

## 最小交付

给出输入与环境、起止边界/缓存状态、测量方法与重复次数、端到端及相关阶段耗时、按口径区分的显存/RAM 峰值、源码证据和下一步验证。仅保留回答问题所需表格或 trace，注明未测项。

API 依据按目标版本查阅：[PyTorch profiler](https://docs.pytorch.org/docs/stable/profiler.html)、[CUDA semantics](https://docs.pytorch.org/docs/stable/notes/cuda.html)、[allocated peak](https://docs.pytorch.org/docs/stable/generated/torch.cuda.memory.max_memory_allocated.html)。
